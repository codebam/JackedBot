# JackedBot — Telegram Multiplayer Blackjack Mini App

Astro 7 SSR + Preact islands on a single Cloudflare Worker, with D1 for the ledger
and one Durable Object per table.

**Live:** `https://jackedbot.codebam.workers.dev` · bot **@JackedBot**

> Chips are **play money**. 1 ⭐ Star = $10.00 of chips. There is no cashout: chips
> cannot be converted to Stars, TON or currency, and no such code path exists.
> 18+ only.

## 1. BotFather setup — everything you need to do

### First: this is a **Mini App**, not a `/newgame`

Telegram has two different things called "game":

| | Legacy **Games** (`/newgame`) | **Mini Apps** ← what this is |
|---|---|---|
| How it's sent | `sendGame` message | inline/menu button or link opening a URL |
| Runtime | `window.Telegram.Game` + `games-api` | `window.Telegram.WebApp` |
| Multiplayer state | you poll `getGameHighScores` | WebSocket to a Durable Object |
| Payments | Stars via `sendInvoice` | Stars via `openInvoice` / `sendInvoice` |

**Do not run `/newgame`** — it will not load this app. Everything below is the Mini
App path.

### What you do **not** need

- **Domain verification** — only required for the Telegram *Login* widget / OIDC on
  external sites (Bot Settings → Web Login) and third-party apps. A Mini App opened
  from your own bot inside Telegram needs none; `workers.dev` HTTPS is fine.
- **Attachment menu** (`/setattach`) — restricted to Telegram Ad Platform
  advertisers; only usable by everyone in the test environment.
- **A `t.me/<bot>/<app>` short link** — those come from `/newapp` for *separate*
  apps. Our links are `https://t.me/JackedBot?app=<url>`, generated by the code.

### Deep links that must keep working

```
https://t.me/JackedBot?startapp            → initData.start_param = ""
https://t.me/JackedBot?startapp=bravo      → start_param = "bravo" (also ?tgWebAppStartParam=bravo)
https://t.me/JackedBot?app=<urlencoded>    → opens that URL as the bot's Mini App
```

`src/lib/config.ts#miniAppLink()` builds the third form from `PUBLIC_ORIGIN`, which
is why that var must be set to the deployed origin.

## 2. Deploy

```bash
npm install                      # postinstall runs `wrangler types`
cp .dev.vars.example .dev.vars   # fill 3 values; see below

npx wrangler login
npx wrangler d1 create jackedbot-db          # paste the returned database_id into wrangler.toml
npm run db:migrate:remote                    # applies schema.sql via migrations/0001_init.sql

npm run deploy                               # astro build && wrangler deploy
# → https://jackedbot.<subdomain>.workers.dev

# Copy that URL into wrangler.toml → PUBLIC_ORIGIN, then:
npm run deploy
npm run secrets:set                          # pushes TELEGRAM_BOT_TOKEN, APP_SECRET, TELEGRAM_WEBHOOK_SECRET
npm run telegram:webhook                     # setWebhook + registers the secret header
npm run telegram:menu                        # setChatMenuButton + setMyCommands
```

`.dev.vars` needs:

| Key | Where it comes from |
|---|---|
| `TELEGRAM_BOT_TOKEN` | **BotFather `/token`** — the only one you get from anyone |
| `APP_SECRET` | **you generate it**: `openssl rand -hex 32` — signs WebSocket tickets |
| `TELEGRAM_WEBHOOK_SECRET` | **you generate it too**: `openssl rand -hex 32`. You store it as a secret *and* hand the same string to Telegram via `setWebhook(secret_token:)`; Telegram echoes it back in `X-Telegram-Bot-Api-Secret-Token` on every delivery. Without it, anyone who finds your workers.dev URL could POST a fake `successful_payment` and mint chips. |

Then message **@JackedBot** → `/start` → Open the lobby.

### Verifying a deployment

```bash
curl -s $ORIGIN/api/health | jq        # d1.ok, durableObjects.ok, secretsPresent
npm run db:drift:remote                # must return zero rows
node scripts/e2e-ws.mjs <telegramId>   # live round over a real socket (needs a seeded local user)
```

## 4. Assets

`scripts/gen-assets.mjs` generates art with **`wan2.7-image`** (a text-to-image model
on the Qwen token plan) and derives every required size locally with `sharp`, then
`scripts/qc-assets.mjs` reviews each image with **`qwen3.8-flash`** (image input) and
fails on garbled lettering, watermarks, anatomy errors or subjects that don't read at
48 px.

```bash
node scripts/gen-assets.mjs                 # generate + derive + size-gate
node scripts/gen-assets.mjs --only banner   # redo one
node scripts/gen-assets.mjs --no-gen        # re-derive from cached assets/raw
node scripts/qc-assets.mjs                  # vision QC gate
```

Upload the files in `assets/botfather/`; `public/` is served by the Worker.
The deterministic SVG emblem (`assets/emblem.svg`) is the fallback and is what ships
as the favicon.

## 5. Operator commands

| Command | What it does |
|---|---|
| `/refund <charge_id>` | `refundStarPayment` **then** claws chips back (capped at the balance, floored at the welcome grant; shortfall journalled to `admin_actions`). `/refund` alone lists recent charges. |
| `/commands` | Re-register the command list. |
| `npm run telegram:webhook -- --check` / `--delete` | Inspect / tear down the webhook. |

Admins are `ADMIN_USER_IDS` (comma-separated Telegram ids) or `roles` containing `admin`.

## 6. Economy knobs

All in `wrangler.toml` `[vars]` / `src/game/rules.ts`:

| Knob | Default |
|---|---|
| `WELCOME_GRANT_CENTS` | `2000` ($20 = two Stars' worth; `0` disables) |
| `BUST_RELIEF_CENTS` | `1000` ($10 credited automatically at exactly $0; `0` disables) |
| `STARS_BUY_IN_AMOUNT` | `1` Star per purchase |
| `DEFAULT_MIN_BET_CENTS` / `DEFAULT_MAX_BET_CENTS` | `100` / `50000` |
| `tables.min_bankroll_cents` | per-table seat price; keeps a free stack off high-roller felt |
| `INITDATA_MAX_AGE_SECONDS` | `86400` |
| `WS_TICKET_TTL_SECONDS` | `60` |
| `RULES.dealerPeeksForBlackjack` | `true` (US peek — players can't act into a dealer natural) |
| `RULES.dealerHitsSoft17` | `false` (stand on all 17s) |

Bust relief: a player who reaches exactly $0 is credited `BUST_RELIEF_CENTS`
automatically, at the felt (on settlement and on sitting down) and on any app launch, so
hitting zero is not a paywall. It is journalled as `admin_adjust` with
`ref_id = 'bust_relief'` — `ledger_entries.reason` is a CHECK constraint SQLite cannot
ALTER, so a new reason value would mean rebuilding the live money journal. The idempotency
key is `relief:<user>:<last ledger id>`, which is what makes "once per bust, unlimited
busts" race-free: two concurrent calls read the same ledger head and the UNIQUE key makes
the loser a no-op, and only a *new* chip movement can unlock the next grant. No cooldown
column, no clock. It deliberately does not touch `welcome_grant_cents`, because that column
is the non-clawbackable floor in Stars refund accounting. Relief is still bounded by each
table's `min_bankroll_cents`, so $10 of house chips cannot buy into high-roller felt.

## 7. Write-budget note

Each round costs ~1 escrow write + ~1 payout write **per seat**, plus one
`rounds`/`round_hands`/`user_stats` batch. A busy 5-seat table at ~30 s/round is
roughly 0.3 D1 writes/s. D1's free tier is 100k writes/day — about 3 tables running
non-stop would exhaust it, so move to a paid tier before scaling the table count.
